# Changelog

## Rename

* Renamed the project from `inspect` to `ipspect` to better reflect its focus on IP and network inspection.

## Ping

* Reworked ICMP discovery from a worker-per-host / socket-per-check model into a shared, event-driven scanner.

* ICMP discovery now uses shared ICMP sockets rather than opening a separate raw socket for every target.

* Added concurrent ICMP probing with up to `500` outstanding probes at once.

* Each active probe now receives its own ICMP sequence number and replies are matched using:

  * source IP
  * ICMP ID
  * sequence number

* Added retry handling:

  * 1 initial Echo Request
  * 3 retries
  * maximum of 4 requests per target

* Reduced the per-attempt ICMP timeout from the previous multi-second wait to a shorter discovery timeout suitable for concurrent scanning.

* ICMP results no longer control the TCP scan scope.

  Previously, only targets that replied to ICMP were retained for port scanning. A host blocking ICMP could therefore be missed even when it had open TCP ports.

  `models.INFO.Targets` now remains unchanged after ICMP discovery, so every original target continues to the TCP SYN scan.

* ICMP-responsive targets are now stored separately in:

```go
models.LOOT.ICMPReachable
```

* ICMP reachability is therefore treated as additional discovery information rather than proof that a host is alive or dead.

## TCP SYN Scan

* Revisited the previously abandoned half-open SYN scan and implemented it as the primary TCP port-discovery method.

* Removed the full TCP connection from the port-discovery stage.

* Port discovery now follows the half-open TCP flow:

```text
SYN
 ↓
SYN/ACK → open → RST

RST     → closed

timeout → filtered
```

* Added raw TCP packet construction, including:

  * source and destination ports
  * sequence numbers
  * TCP flags
  * TCP checksum calculation
  * IPv4 pseudo-header checksum

* Added a shared raw TCP receiver for scan responses.

* Added event-driven tracking of outstanding SYN probes rather than creating one blocking TCP connection per port.

* Added a concurrent SYN window of up to `500` outstanding probes.

* Responses are correlated with pending probes using:

  * target IP
  * source port
  * destination port
  * TCP sequence / acknowledgement numbers

* Open ports receiving `SYN/ACK` are terminated with `RST` instead of completing the TCP three-way handshake.

* Port states are now stored separately in each host result:

```go
Ports
Closed
Filtered
Details
```

* Closed ports continue to be omitted from detailed results during the default `1-65535` scan to avoid storing and printing tens of thousands of unnecessary entries.

* When `-p` is explicitly supplied, closed ports are retained in `Details` and shown in the final results.

Example:

```text
open     [80, 443]
closed   [21, 22]
filtered 0
```

## Port Selection

* Extended `-p` beyond a single port or continuous range.

* `-p` now accepts individual ports:

```bash
-p 22
```

* Port ranges:

```bash
-p 1-1024
```

* Comma-separated port lists:

```bash
-p 21,22,80,443
```

* Mixed lists and ranges:

```bash
-p 21,22,80,443,8000-8100
```

* Added:

```go
models.INFO.Ports
models.INFO.PortSpec
```

* Explicit port selections are expanded internally into a sorted port list.

* Duplicate ports are removed automatically.

* The SYN scanner now iterates the explicit port list instead of assuming every scan is a continuous `PortStart` → `PortEnd` range.

## Enrichment

* Port discovery and port enrichment are now fully separated.

* The SYN scan is responsible only for determining port state.

* Full TCP connections are now made only for ports already identified as open.

* Reworked enrichment into a concurrent worker pool.

* Added `128` enrichment workers so multiple open ports can be inspected simultaneously.

* Split enrichment responsibilities into separate functions instead of keeping all logic inside `enrich()`.

Current flow:

```text
enrich()
    ↓
worker pool
    ↓
enrichPort()
    ↓
    ├── enrichTCP()
    └── enrichHTTP()
```

* `enrichTCP()` handles generic TCP services and passive banner reads.

* `enrichHTTP()` handles HTTP/HTTPS-specific probing.

* `openHTTPConnection()` handles the distinction between normal TCP and TLS connections.

* Connection latency continues to be recorded during the enrichment connection.

## HTTP / HTTPS

* Expanded HTTP enrichment beyond reading only the HTTP status line.

* HTTP and HTTPS services now send an explicit request containing:

```http
GET / HTTP/1.0
Host: <target>
User-Agent: ipspect
Connection: close
```

* HTTPS enrichment continues to use TLS with certificate verification disabled because the connection is used for service inspection rather than trust validation.

* Added HTTP response-header collection.

* Added a dedicated `header_grab.go` parser using `net/textproto`.

* `PortDetail` now stores:

```go
Headers map[string][]string
```

* The HTTP status line remains the port banner.

* HTTP headers are collected from the same TCP/TLS connection used for the HTTP enrichment request.

  No additional connection is created just for header collection.

## Results

* Final output now supports HTTP headers underneath the corresponding port result.

* Headers are sorted before printing to keep output deterministic.

* Explicitly selected closed ports are now included in the detailed result table.

Example:

```text
HOST    192.168.1.105
PORT    STATE   SERVICE   BANNER               LATENCY
21      closed
22      closed
80      open    http      HTTP/1.1 200 OK      1.2ms
                         Content-Type:         text/html
                         Server:               nginx
```

## Saved Results

* Markdown output now records ICMP-responsive targets separately.

* Saved reports now preserve the exact port specification supplied by the user through `PortSpec`.

For example:

```text
-p 22
```

is saved as:

```text
Ports: 22
```

and:

```text
-p 22,80,443,8000-8100
```

is saved as:

```text
Ports: 22,80,443,8000-8100
```

rather than incorrectly representing the selection as one continuous range.

* Saved reports now include HTTP response headers grouped under the port from which they were retrieved.

* Saved results now distinguish between:

  * ICMP reachability
  * TCP port state
  * service information
  * banners
  * HTTP headers
  * connection latency

## Models

* `PortDetail` now includes HTTP headers:

```go
type PortDetail struct {
    Port    int
    State   string
    Service string
    Banner  string
    Headers map[string][]string
    Latency time.Duration
}
```

* `HostResult` now tracks closed ports separately:

```go
type HostResult struct {
    Target   string
    Ports    []int
    Closed   []int
    Filtered []int
    Details  []PortDetail
}
```

* `LOOT` now separately records ICMP-responsive hosts:

```go
var LOOT struct {
    ICMPReachable []string
    Hosts         []HostResult
}
```

* `INFO` now stores both the expanded port list and the original port specification:

```go
Ports    []int
PortSpec string
```

## Current Scan Flow

The scanner now follows this architecture:

```text
targets
   ↓
concurrent ICMP discovery
   ↓
record ICMP responders
   ↓
keep ALL original targets
   ↓
concurrent half-open SYN scan
   ↓
open / closed / filtered
   ↓
open ports only
   ↓
concurrent full-TCP enrichment
   ↓
service / banner / HTTP headers / latency
   ↓
terminal + Markdown results
```

The main architectural change since the previous changelog is that `ipspect` no longer uses full TCP connections for port discovery. Full connections are reserved for enrichment after the half-open SYN stage has already identified an open port.
