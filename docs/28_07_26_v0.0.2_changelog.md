# Changelog

## Ping

- `Ping()` no longer treats a failed ICMP echo as fatal. Previously, `!ok` triggered `os.Exit(0)`, halting execution entirely if a host didn't respond to ICMP.
- Message wording changed from "is alive" / "is dead" to "is accepting echo requests" / "is not accepting echo requests" — more accurate, since a non-response doesn't prove the host is down, only that it isn't replying to ICMP.
- `cmd.ping()` updated to print an additional "inspecting anyways." note when `ok` is `false`, then falls through to the port scan regardless of ICMP result.

## Port scan

- Explored a hand-rolled SYN (half-open) scan as a faster alternative to the full TCP connect scan. Identified a structural blocker: the local kernel's TCP stack intercepts incoming SYN-ACKs it doesn't recognize and sends its own RST, corrupting scan results unless suppressed via an iptables/nftables rule. Decision: not implemented, since modifying iptables was ruled out. Staying with the connect scan (`port_search()`).
- Added port state classification beyond a binary open/not-open:
  - `classifyError(err)` distinguishes `"closed"` (active refusal, `ECONNREFUSED`) from `"filtered"` (timeout or any other non-refusal error).
  - `port_search()` now records `"open"` and `"filtered"` ports into `models.LOOT.Details`. `"closed"` ports are classified but discarded, not recorded.
  - `models.LOOT.Ports` (the simple open-ports list) is unchanged — still only populated for `"open"` ports.
